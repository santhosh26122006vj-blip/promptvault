# PromptVault — Firestore Database Reference

This document describes the Firestore collections and fields used by PromptVault. Useful for explaining the data model during a project demo or viva.

---

## 1. `users` Collection

**Document ID:** Firebase Auth UID (same as the logged-in user's `uid`)

| Field | Type | Description |
|---|---|---|
| `name` | string | User's display name |
| `email` | string | User's email address |
| `photoURL` | string | URL to profile picture in Firebase Storage (empty string if not set) |
| `createdAt` | timestamp | Account creation time (`serverTimestamp()`) |

**Example document** (`users/AbC123xyz`):
```json
{
  "name": "Santhosh",
  "email": "user@example.com",
  "photoURL": "https://firebasestorage.googleapis.com/.../profilePictures%2FAbC123xyz",
  "createdAt": "2026-08-04T10:15:00Z"
}
```

---

## 2. `prompts` Collection

**Document ID:** Auto-generated by Firestore (`addDoc`)

| Field | Type | Description |
|---|---|---|
| `title` | string | Prompt title |
| `content` | string | Full prompt text |
| `category` | string | User category name; kept as a string for backward compatibility |
| `tags` | array\<string\> | Optional keyword tags |
| `aiModel` | string | AI model the prompt was written for (e.g. "ChatGPT", "Claude") |
| `ownerId` | string | Auth UID of the creator (used for security rules) |
| `createdAt` | timestamp | Creation time (`serverTimestamp()`) |

**Example document** (`prompts/xYz789`):
```json
{
  "title": "Instagram Caption Generator",
  "content": "Write 5 catchy Instagram captions for a coffee shop post...",
  "category": "Social Media",
  "tags": ["instagram", "marketing", "captions"],
  "aiModel": "ChatGPT",
  "ownerId": "AbC123xyz",
  "createdAt": "2026-08-04T10:20:00Z"
}
```

---

## 3. `favorites` Collection

**Document ID convention:** `{userId}_{promptId}` (composite key, prevents duplicate favorites for the same prompt)

| Field | Type | Description |
|---|---|---|
| `userId` | string | Auth UID of the user who favorited the prompt |
| `promptId` | string | ID of the favorited document in `prompts` |
| `createdAt` | timestamp | When it was favorited |

**Example document** (`favorites/AbC123xyz_xYz789`):
```json
{
  "userId": "AbC123xyz",
  "promptId": "xYz789",
  "createdAt": "2026-08-04T10:22:00Z"
}
```

## 4. `users/{uid}/categories` Subcollection

Categories are now stored per authenticated user. This is additive: the existing `prompts.category` string field is intentionally kept so current prompt documents do not need a destructive migration.

| Field | Type | Description |
|---|---|---|
| `name` | string | User-visible category name |
| `ownerId` | string | Auth UID of the owner |
| `isBuiltin` | boolean | Whether it came from the original built-in list |
| `isFallback` | boolean | `true` only for protected `Uncategorized` |
| `createdAt` | timestamp | Category creation time |

### Backward compatibility

When an existing user opens the updated dashboard, the original built-in categories are created in their own category subcollection if they are missing. Any category names already present on their old prompts are also preserved. Existing prompt documents are not rewritten during this initialization.

Users can add, rename, and delete categories. Renaming updates only that user's prompts from the old category name to the new name. Deleting a category moves its prompts to `Uncategorized` instead of deleting them. `Uncategorized` is protected so there is always a safe destination for prompts when a category is removed.

## 4. Why This Structure?

- **Separate `favorites` collection** (instead of a boolean field on `prompts`) keeps favorite-toggling fast and avoids re-writing the whole prompt document every time a user favorites/unfavorites it.
- **`ownerId` on every prompt** is what makes the Firestore Security Rules in `firestore.rules` work — each rule checks `resource.data.ownerId == request.auth.uid` before allowing read/write access.
- **Composite document IDs** in `favorites` (`userId_promptId`) let the app check "is this favorited?" and toggle it with a single, predictable document reference instead of running a query.

## 5. Relationships Diagram (Conceptual)

```
users (1) ───────────┐
  │                   │ ownerId
  │ uid                ▼
  │              prompts (many)
  │                   │
  │ userId             │ promptId
  ▼                    ▼
favorites (many, one per user-prompt pair)
```
